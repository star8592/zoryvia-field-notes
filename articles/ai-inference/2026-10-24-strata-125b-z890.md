# RTX 5070 Ti + 96GB 内存部署 Strata 125B：一次真实安装实录

> 状态：**VERIFIED（单机加载、短客服问答、S8 USB 联调范围内）** · 日期：2026-10-24。仍非长期稳定性或正式客户自动回复的验收。

## 为什么做这个实验

目标是在消费级台式机上运行 125B 参数的 MoE 大模型，以本地 AI 承接商品客服问答。手机端 Android APP 负责监听、理解消息上下文与操作原生聊天界面，AI 推理端在 Linux 电脑上；发货机器人与客服机器人在业务职责上隔离，支付/履约状态必须由可信订单状态核验。

Strata 的 MoE 专家动态调度技术值得验证，但“作者机器上快”不等于“自己的设备上快”，因此记录了实际安装和测试回执。

## 机器及 SSD 环境（实机确认）

| 项目 | 实际配置 |
|---|---|
| GPU | RTX 5070 Ti，约 16GB 显存 |
| 内存 | 标称 96GB，Linux 显示 91GiB |
| Linux | Ubuntu 26.04.1 LTS |
| Data 盘 | Samsung 990 EVO Plus 1TB NVMe SSD，ext4 |
| Data 盘容量 | 文件系统显示 916G，安装前可用约 555G |
| NVIDIA 驱动 | 615.71.09 |

安装时发现 Data SSD 已存放 CI、视频和虚拟机项目，约 315G 已用。**我们没有删除这些可能仍被使用的数据**，而是创建独立目录存放 Strata 及权重文件。SSD 权重加载与操作系统现有任务相互隔离。

## 第一个问题：已有 llama.cpp 二进制缺共享库

检查系统时，旧 `llama-server` 提示缺少 `libllama-server-impl.so`。我们没有为了 Strata 项目直接修改系统共享库、重装全局 CUDA 或调整现有驱动，因为那个二进制的状态并不代表 Strata 有问题。另行部署，避免污染其他项目。

## 第二个问题：Git sparse-checkout 的指定方法

拉取 Strata 源码时，最初向 `git sparse-checkout set` 传入多个 Markdown 文件路径，cone 模式下返回退出码 128。改为直接指定目录 `docs` 后取回文档成功。这类工具边角问题很容易被写教程时忽略，却经常拖慢真实安装。

## 安装实际回执

1. 从官方 GitHub Releases **下载并先审查** `install.sh`，没有直接使用 `curl | sh`。
2. 安装器 SHA-256 为 `73a3e0cbd8f2f00e1f26a304c1f8f498afdf9be3a4a9f58c83fa5ffdb6642780`（仅对应本次下载的文件）。
3. 通过官方支持的 `STRATA_DATA_DIR` 与 `STRATA_BIN_DIR` 参数指定 Data SSD 安装路径，而不是写进用户主目录。
4. 安装 CLI `strata 0.2.4.1`（Terminal build `0.1.49.1`），安装器返回 `Checksum ok` 和 `Signature ok`。
5. 调用 `strata launch --plan` 检查 Qwen3.8-Flash-Next `IQ3_S`，设置 `32k` 上下文、`vision off`、单并发、`access local`；预检给出约 **83.6 GB** 模型权重和 **5.2 GB** 加速层，合计约 88.8GB 下载计划。
6. 单独下载 CUDA 13 推理引擎 `0.1.48`（约 578MiB），经过签名、逐文件校验和启动测试，已成功激活。
7. 2026-10-24 下午：两份权重及准备过程已完成，但 MTP 加速层因 Hugging Face 连接中断而安装失败。复用已下载权重，显式增加 `--mtp off --drafting off` 后成功加载 125B，并返回 API `loaded`。

执行命令示例（请按本机路径调整）：

```bash
STRATA_DATA_DIR=/path/to/ssd/strata-runtime \
STRATA_BIN_DIR=/path/to/ssd/strata-bin \
sh ./install.sh

/path/to/ssd/strata-bin/strata launch --plan \
  --family qwen --model iq3_s \
  --data-dir /path/to/ssd/models --context 32k \
  --vision off --parallel 1 --port 18090 \
  --access local --output json
```

默认将模型 API 仅绑定本机环回接口。给其他设备调用时，需要先设计认证和受控网络，不能把无鉴权端口直接开放到公网。

## 与客服应用关系

此前在同一主机通过 Ollama 运行较小的 Qwen3.8 9B，禁用思考输出后，一个模拟的中文售前问题生成正式答复耗时约 **2.88 秒**。这一数值来自 **9B + Ollama**，**不能冒充 Strata 125B 的性能**。

预计模型加载成功后测试：真实首 token 延迟、输出 tokens/s、显存和系统内存占用、30 条客服样题的正确性、重复提问的稳定性，以及咨询/付款/发货意图分流。

## 2026-10-24 更新：成功加载与真实首测

第一轮 `max_tokens=180` 未得到可见正式答复：默认思考模式用尽输出预算，`finish_reason=length`。这不是“125B 模型没跑起来”，而是请求没有适配模型的思考设置。

改为 `"reasoning_effort": "none"` 与 `"chat_template_kwargs": {"enable_thinking": false}`，同样的中文售前问题正式返回了可见答复。**单次实测**耗时 0.984 秒，输出 39 tokens，Strata 返回的 `timings.predicted_per_second` 为 **85.8 tokens/s**；提示词约 67 tokens。此前文中 9B + Ollama 的耗时 2.88 秒来自不同条件，不是严格同提示词的性能基准。

随后在实际 Samsung S8 Android 9 上安装独立客服 APP `v0.1.4`，以 Android `adb reverse` 经 USB 本地回环连接 Strata `/v1/chat/completions`，成功取得如下中文草稿：

> 您好！目前我这边暂未获取到该商品的具体目录和样张信息，无法直接确认是否有七大类专题或提供预览。为了准确回答您，请问您具体关注的是哪一类专题内容呢？

**运行资源：** 5070 Ti 总显存 16303 MiB，Strata 运行时总显存占用约 15.7GiB；系统内存使用约 59GiB（机器总物理内存约 91GiB）。这一配置显存余量偏低，不能同时假设其他 GPU 工作负载安全。长问题、并发、重启恢复和长期运行没有证明。MTP 下载问题仍未解决，本次验证仅使用禁用 MTP 的模式。

## 续篇：125B 安装完成后，还缺哪些生产条件？（2026-10-24）

这次实验把「安装能启动」「接口能回答」「手机可以独立使用」分为**不同的验收等级**，避免同一张成功截图被误认为整个业务上线。

### 1. 核心模型已经安装完成，MTP 不是启动依赖

Strata `0.2.4.1`、CUDA 引擎和两份 IQ3_S 权重完整落在 NVMe Data SSD。基础模型启动后 `/v1/models` HTTP 200，返回 `qwen3.8-flash-next-iq3_s` 与 `loaded`；手机经 USB 反向端口调用模型完成中文客服问答。MTP 草稿加速层此前因下载连接问题未完成；我们采用 `--mtp off --drafting off` 避免重新下载数十 GB 权重。

**重要**：实际显存占用约 15.7GB / 16.3GB，空闲显存只有数百 MB。即使下载成功，也不能断言 MTP/DFlash 能在同一显卡负载下稳定启用。此阶段优先做稳定性，而不是把额外组件都装上。

### 2. 用用户级 systemd 守护运行，不干扰已有模型进程

新增了独立的 Strata 健康守护任务，部署后 `systemctl --user is-active` 返回 `active`，`is-enabled` 返回 `enabled`，配置了 user linger。守护进程每隔一段时间读取 `/v1/models`，只有在模型端口消失、且显存与可用 RAM 达到安全余量时才尝试恢复；端口虽存在但仍加载中时不会盲目起第二份模型。

这次启动服务时核对了原始 PID，确认它**没有重启当前正常运行的 125B 模型**。但系统异常退出、网络断开、重启和 24 小时连续运行的完整故障注入尚未完成，因此只能标记为「守护服务安装且健康检查通过」，不能冒充「自动恢复全部验收完成」。

### 3. 本地推理不能直接暴露无鉴权 API

原生 Strata 继续只监听 `127.0.0.1`。另设私有 Nginx TLS 1.2/1.3 网关，只允许带独立设备令牌的指定 POST 推理路径通过；禁用请求访问日志，其他路径返回 404。真实测试验证：无令牌与错误令牌都返回 401，经过私有 CA 校验的正确授权请求能够得到 125B 生成的中文回复。

Android 端则加入了私有 CA 证书及主机名验证、设备令牌的 AndroidKeyStore AES-GCM 加密存储代码。使用 USB 转发（仅测试用）让手机访问 HTTPS 网关，不提供令牌时，APP 实际显示「证书与主机名校验通过，HTTP 401」——**这说明 TLS 工作正常，不等于客户端已完成令牌配对**。请勿把真实密钥放入 Git、公开截图、教程命令行或 APK 常量中。

### 4. 为什么手机还不能拔线？

本次手机和 Z890 所在 Wi-Fi 网段不同，手机到主机的局域网探测未得到响应。换成 HTTPS 不能自动解决路由问题；需要先建立可互通的可信局域网或私有加密网络，并验证证书 SAN、令牌和权限。**脱离 USB 的实际数据通路仍未完成测试**。

此外，客服真实上线还需要可信商品与聊天会话绑定、发货机器人同屏互斥、原生 IM 发送回执与去重；仅有 125B 回答示例并不表示这些业务环节已完成。

**阶段结论**：125B 的基础安装与单用户短问答已成功；MTP 是可选未完成项；守护服务、HTTPS 网关已部署；手机客户端的证书校验通过，但安全配对、跨网段移动网络访问与真实客服发送尚待验收。资料将随真实验证进度更新，不用估测结果替代现场证据。

## 第二阶段：12 条连续客服短问答及跨网段单向访问验证（2026-10-24 19:30）

125B 基础模型继续采用 `--mtp off --drafting off`，推理端已保持加载。由 Z890 本机直接调用 OpenAI-compatible `/v1/chat/completions`，统一设定 `reasoning_effort="none"`、`chat_template_kwargs.enable_thinking=false`、最大输出 90 tokens、单并发。12 条相互独立、泛化的中文售前短问题（仅询问已知资料类型和目录是否可核实）全部得到可见正式答复：**12/12 PASS**，延迟中位数 **0.645 秒**，最长 **0.735 秒**。生成后 `/v1/models` 仍显示模型 `loaded`，显存占用 **15677/16303 MiB**，GPU 温度约 65℃。

这组连续短答数据只说明当前硬件的轻负载客服场景有希望，不等于真实客户长对话上下文、并发、全天稳定运行或自动发送成功，也不是 MTP 开启后的成绩。原始机器侧验收文件为 `/mnt/data/strata-customer-ai/benchmarks/2026-10-24-soak-12.json`（未上传敏感运行环境配置）。

网络诊断进一步发现：**Z890 → S8** ping 成功，**S8 → Z890** ping 失败。两台机器分属不同 IPv4 网段。随后在 S8 上临时启动一个只返回静态测试字符串的单次 TCP 监听端口，Z890 直接 TCP 连接得到 `S8_TCP_ONE_SHOT_OK`，接入结束后同端口再次连接失败，验证临时监听确实已关闭。证明当前网络允许**由 Z890 主动发起的 TCP 建连**，但尚未完成 TLS 相互认证或业务数据传输。

正确后续路线是：在 Android 端建立具有明确用户授权、身份校验、限流与前台服务生命周期的反向安全通道，Z890 作为主动连接方；如果要支持 4G/跨地区则需要独立中转或 VPN。绝不能把临时 TCP 连通测试写成「手机拔线后 AI 已通」，也不能用开放 ADB 调试端口 5555 代替商用网络通道。
