# Windows 六种格式都能播，三星 Android 9 却不支持 AV1：一次真机兼容性排障

> 状态：**VERIFIED（受控测试范围内）** · 实测日期：2026-10-13，补充验证：2026-10-14。所有视频由测试程序合成或采用公开测试素材，不涉及商业片源。

一台电脑上的浏览器能播放 AV1，是否意味着旧安卓手机也能播放？我们在构建一个「客户端直连媒体来源」的实验原型时，得到的答案是：**不能。** 这也促使我们把“浏览器可播”和“设备解码能力”拆成独立验收。

## 实验设计

- 开发主机：Ubuntu Linux，Rust 服务提供页面和播放策略；媒体数据并不通过 Rust 服务中转。
- Windows 测试：Chrome 155，使用独立临时浏览器配置和局域网合成媒体源。
- Android 测试：Samsung Galaxy S8（SM-G950U），Android 9；通过设备系统的 MediaCodec 原生 API 解码，不启动手机浏览器 UI。
- 测试内容：H.264/AAC MP4、Fragmented MP4、HEVC/AAC MP4、AV1/AAC MP4、VP9/Opus WebM、H.264/AAC MKV。

## 第一个坑：六种视频一开始全失败，真的是解码器不支持吗？

Windows 的第一轮实验从 `about:blank` 状态进行导航和媒体加载，六个用例都失败。我们没有立即归咎于编解码器，而是改变一个变量：把网页放在真实的 HTTP Origin 上，再加载另一个 HTTP 端口上的媒体资源。

**复测：六种媒体在 Chrome 中均推进了约 0.86 秒，媒体错误均为 null。** 另外，媒体源真实返回了 `HTTP 206 Range`，页面请求是 200。

这并不证明浏览器“任意跨域都能播放”，也不能证明 `about:blank` 失败的唯一根因。它说明播放测试必须控制页面来源、浏览器安全上下文和请求路径，否则可能得到假阴性。

## 第二个坑：浏览器能解 AV1，不代表老手机原生解码也能

我们在 Samsung S8 上直接调用系统 MediaCodec，对六个三秒合成文件逐个解码。结果：

| 格式 | 实测输出帧 | 结果 |
|---|---:|---|
| H.264/AAC MP4 | 73 | PASS |
| Fragmented MP4 | 73 | PASS |
| HEVC/AAC MP4 | 73 | PASS |
| VP9/Opus WebM | 73 | PASS |
| H.264/AAC MKV | 73 | PASS |
| AV1/AAC MP4 | 0 | FAIL |

AV1 失败时，系统媒体提取器返回 `video/unknown`，设备未提供本次所需的 `video/av01` 解码器。需要说明的是，这验证的是系统原生解码能力，**不是** Android Chrome 的页面/渲染链路。不能将两者的结果混为一谈。

## 第三个坑：弱网恢复功能可能“好心办坏事”

10 月 14 日进行 Wi-Fi 关闭与恢复实验时，发现视频仍在正常播放，但旧逻辑在网络重新连通时多做了一次播放器重载。修复规则很简单：只有在视频实际停止推进、处于不可继续播放状态时才考虑恢复；如果播放时间轴仍在前进且 `readyState >= 3`，记录状态即可，不主动重载。

重新测试时，手机 Wi-Fi 断开约 8 秒后恢复，播放时间轴从约 1.73 秒推进到 23.79 秒，额外自动重连次数从 1 次降为 0 次。这是受控单机测试结果，不代表所有运营商网络或 CDN 都无感恢复。

我们又对长视频的真实 HTTP TCP 响应进行一次主动中途切断。Chrome 通过第二次 Range 请求恢复播放；实测程序自身 `autoRetries=0`。这次恢复应归功于浏览器，而**不能包装成我们自己实现了网络层断点重连**。

## 最终工程原则

1. 不同平台的解码能力要分设备和 API 层面验证，而不是只列出理论支持矩阵。
2. 模拟故障要确认真正触发了网络 I/O，不能把浏览器缓存造成的“继续播放”当作弱网能力。
3. 有的故障浏览器已经恢复，应用层应避免重复介入。
4. 原型测试结论必须限制在设备、系统、媒体样本和网络条件之内。

## 回归记录和局限

- Windows Chrome：六种媒体实测播放推进，结果均通过。
- Samsung S8 / Android 9：原生解码 5/6，通过五项，AV1 不支持。
- 后续 Wi-Fi/断流受控测试：单次恢复成功；Rust 项目 12/12 单测通过。
- 未证明：公网生产级 SLA、全部 Android 版本、iOS/Safari、DRM、所有 CDN、长期运行与公网带宽成本。
